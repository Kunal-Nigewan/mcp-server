USE CASE 01

AI Travel Planner

A representative workflow demonstrating how the MCP server can be used to analyze and test an agentic workflow.

SIMULATED WORKFLOW

Imagine planning a three-day trip to Goa. Instead of manually checking flights, hotels, weather forecasts, and activities separately, an AI-powered workflow can organize these tasks into a sequence of steps.

Step 1 — Tell the planner what you need. The user's request becomes the input for the workflow.

Step 2 — Gather travel information. The workflow searches for flights and hotels and checks the weather to gather information for the trip.

Step 3 — Build the itinerary. The gathered results are combined to create a proposed itinerary for the trip.

Step 4 — Analyze and test the workflow. AgenticLens can help analyze workflow behavior and available evidence. Agentic Chaos can run controlled fault experiments to investigate how the workflow behaves under selected failure conditions.

What do you get? A proposed travel itinerary and an example of how the MCP server's analysis and resilience-testing capabilities can be applied to an AI workflow.

USE CASE 02

Workflow Fault Testing

Controlled fault experiments help teams investigate how an agentic workflow behaves when selected failure conditions occur. Agentic Chaos provides capabilities for discovering supported faults and running configured experiments.

Illustrative Workflow

How It Works

Step 1 — Identify available faults: Inspect the fault scenarios supported by the configured Agentic Chaos integration.

Step 2 — Run an experiment: Select an appropriate fault scenario and execute a controlled experiment using the required configuration.

Step 3 — Review the results: Examine the returned output to investigate possible failure points and understand workflow behavior.

Outcome: Evidence that can help a team assess workflow resilience and identify areas for further investigation.

USE CASE 03

AI Evaluation and Release Gate

Before releasing an updated AI workflow, teams can analyze its behavior, compare baseline and candidate runs, and review evaluation evidence against their release requirements.

Illustrative Workflow

How It Works

Step 1 — Analyze workflow behavior: Examine an available workflow run using AgenticLens analysis capabilities.

Step 2 — Compare runs: Compare a baseline run with a candidate run to inspect differences in their available results.

Step 3 — Review service-level objectives: Inspect the available SLO summary to assess relevant service-level indicators.

Step 4 — Generate audit evidence: Produce an audit report and review the available evidence against the team's release criteria.

Outcome: Structured evidence that helps a team evaluate release readiness and make an informed release decision.

# 4. Generate audit evidence
lens.audit_report(...)

These tools provide evidence for evaluation. The team applies its own release criteria; the sequence is not a built-in automatic release approval mechanism.
